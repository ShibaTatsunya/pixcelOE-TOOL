# pixcelOE 路线图

版本演进记录与后续功能规划。功能排期按「价值 / 风险」权衡，**任何改动都不得破坏既有能力**（算法与产线逐像素一致、4 项验收、导出 PNG+JSON），每次改动跑全量测试后才算完成。

## 已完成

### v1.0（本地 git 提交 `e5ff8a1`）

- 核心算法：`posterize.py` + `pixelize_oe.py` 的逐行移植，与产线逐像素一致（`test_consistency.py` 9/9）。
- 两栏界面：左参数（5 组通俗化）、中预览。
- 参数：黑白化算法 / Gamma / 亮度 / 对比度 / 灰阶层数 / 分层方式 / 细节敏感度 / 线条粗细 / 保留细线 / 缩小倍数（无级，边缘补齐不裁内容）/ 像素块取值方式（bridge 等 5 种）/ 暗线保留强度 / 调色板 / 颜色数 / 目标画布。
- 预览交互：适应（浮点精确适配）、滚轮缩放、1x~8x 按钮、像素网格、成品/原图/并排（等高）三种视图、左键拖动平移。
- 底部状态栏：尺寸、耗时、验收（`✓ n/4`）。
- 导出：PNG + 同名 JSON 元数据（含完整参数与验收结果）。
- 后端零依赖（标准库 http.server），前端原生 JS 无框架。

## 参考网络像素转换器后的规划

参考：[PixelIt](https://github.com/arcos-dev/pixelit-ui)、[image2pixel](https://github.com/32comic/image2pixel-web)、[Image-to-Pixel](https://github.com/Tezumie/Image-to-Pixel)。这些工具普遍提供：调色板控制、抖动、预设、色深、缩放、导出。

| 优先级 | 功能 | 价值 | 风险 | 状态 |
|---|---|---|---|---|
| P0 | 预设保存/加载（localStorage） | 高（用户反复调参） | 低（纯前端） | 待做 |
| P0 | 导出缩放倍数（1x/2x/4x） | 高（直接用于游戏） | 低 | 待做 |
| P1 | 抖动（bayer 有序抖动，产线已有算法） | 高（灰阶过渡更丰富） | 中（需移植 dither 逻辑） | 待做 |
| P1 | 自定义调色板（粘贴 hex / 上传 .gpl） | 中 | 中 | 待做 |
| P2 | 批量处理（多图队列） | 高 | 高（队列/进度/内存） | 待做 |
| P2 | 操作历史（撤销/重做参数） | 中 | 中 | 待做 |
| P3 | 快捷键面板、导出历史 | 低 | 低 | 待做 |

## 约束（不可违反）

1. 算法输出必须与 `mengshi-art-workflow/scripts/` 产线脚本逐像素一致（`test_consistency.py` 守住）。
2. 4 项验收口径与 `validate_asset.py` 一致。
3. 后端零第三方依赖；前端无框架、离线可用。
4. 不上传 git（除非用户明确同意）。
