# pixcelOE · 图片转像素图工具

把**已经画好或生成好的插画**，按《梦蚀 DEMO》的像素化产线转成像素图 —— 所有关键参数都能在网页界面里实时拖动、实时看结果。

> **它做什么**：后处理（去饱和 → 色调分离 → 轮廓扩展 → 对比度感知降采样 → 调色板量化），也就是产线里 `posterize.py` + `pixelize_oe.py` 那一段。
>
> **它不做什么**：不做 AI 生成（生成仍在 ComfyUI 里完成），不联网、不上传、不写工作区以外的地方。

---

## 1. 快速开始

**最简单**：双击 `启动.bat`（会自动检查依赖、启动服务、打开浏览器）。

**命令行**：

```bash
python app.py                  # 默认 127.0.0.1:8760，自动开浏览器
python app.py --port 9000      # 换端口（被占用时会自动往后找）
python app.py --no-browser     # 只起服务
```

依赖只有 `numpy` 和 `Pillow`，没有 Web 框架、没有打包步骤：

```bash
pip install numpy pillow
```

服务只监听 `127.0.0.1`，同一局域网内的其他机器访问不到。

## 2. 界面

两栏布局：

| 栏位 | 内容 |
|---|---|
| 左 · 参数 | 5 组参数（输入与明暗 / 灰阶分几层 / 轮廓与线条 / 像素块大小 / 颜色与画布），可切「角色预设 / 场景预设」 |
| 中 · 预览 | 拖入图片即出结果；4 种视图（成品 / 原图 / 并排 / 混合）、滚轮 + 按钮缩放、像素网格开关；底部状态栏显示尺寸、耗时与验收结果 |

**操作要点**

- 直接把图片**拖进窗口**，或点「选择图片」。
- 参数一次只动一个，结果会自动重算（拖滑块时做了 260 ms 防抖）。
- 「并排」和「混合」用来核对像素化前后的对应关系；「像素网格」用来检查有没有半像素错位。
- 在画布上**滚动滚轮**即可缩放（向上滚放大、向下滚缩小，在 1x~16x 整数倍间切换）。
- 点顶部「导出 PNG」（或按 `Ctrl+S`），输入文件名即保存到 `outputs/`，**同时生成同名 `.json` 元数据**（记录完整参数与验收结果），方便回溯。

## 3. 算法链路

```
输入 RGB 大图（如 640×960）
   │
   ├─ 1. 去饱和 + 色调分离     posterize()
   │       HSL 去饱和 → PS 亮度/对比度 → floor 分档（4 档 = 0/85/170/255）
   │
   ├─ 2. 轮廓扩展              outline_expand()
   │       局部 min/max/median → 对比度权重 → 腐蚀/膨胀混合 → 闭运算补断线 → 开运算去噪
   │       让 1~2px 的细线在缩小后仍能存活
   │
   ├─ 3. 对比度感知降采样       contrast_downsample()
   │       块内按偏斜取极值，而不是求平均 —— 这是"像素化"与"缩略图"的分界
   │
   └─ 4. 调色板量化            nearest_palette()
           固定调色板最近色映射（禁止"每图统计取前 N 色"）
   ▼
输出像素小图（如 160×240）
```

第 3 步的**块内取值策略**是整条链里最影响观感的一个开关：

| 策略 | 行为 | 何时用 |
|---|---|---|
| `bridge` | 只补缺口：本该取亮值却含暗线的块改取最暗 | **默认**。线连得上且不加粗，实测脆度最高 |
| `skew` | 原始行为：按块内偏斜取极值 | 对照用 —— 轮廓会断成虚线 |
| `dark` | 全局暗线保护 | 需要实线但能接受线变粗、画面变闷 |
| `edge` | 只保护沾到亮底的块 | 实测无效，保留对照 |
| `median` | 一律取块中值 | 碎段消失，但暗线整体变浅 |

## 4. 参数速查

| 参数 | 默认 | 说明 |
|---|---|---|
| 跳过去饱和/分档 | 关 | 输入本身已是分档灰图时勾选 |
| 去饱和算法 | `hsl` | `HSL` 取 `(max+min)/2`，等价于 PS 把饱和度拉到 −100；`rec709` 是旧行为 |
| Gamma / 亮度 / 对比度 | 1 / 0 / 60 | 对齐 PS「亮度/对比度」调整层 |
| 灰阶档数 | 4 | 0 = 不分档；4 对应 PS「色调分离 4」 |
| 分档算法 | `ps` | 用 floor 分档（真实 PS 行为），不是「取最近档」 |
| patch | 2 | 局部统计窗口半径 |
| thickness | 1 | 形态学半径，轮廓加粗程度 |
| keep-thin | 关 | 跳过开运算，保住睫毛 / 嘴唇线 / 衣物缝线 |
| factor | 4 | 缩小倍数（像素块粗细），640×960 → 160×240；**任意值可用，无需尺寸整除** |
| dark-line | 0.06 | 块内最暗值比中位暗多少才算「有暗线」 |
| 调色板 | 角色套 | 角色 8 档 / 场景 7 档 |
| 量化档数 | 4 | 0 = 完整调色板；4 = 在调色板内等距抽 4 档 |
| 验收画布 | `160x240` | 留空则不检查尺寸 |

两个预设：

- **角色预设**：`factor=4`、4 档、`contrast=60`、`bridge`、角色套、画布 `160×240`
- **场景预设**：`factor=2`、4 档、`contrast=40`、`bridge`、场景套、画布 `640×360`

## 5. 交付验收

每次转换后，底部状态栏会自动跑 4 项机械检查并显示「验收 ✓ n/4」或「验收 ✗ n/4」（对应工作区 `AGENTS.md` §6.1）：

| 检查 | 判定 |
|---|---|
| 尺寸符合画布 | 输出尺寸 == 指定画布（填了才检查） |
| 边缘无半透明 | 所有 alpha ∈ {0, 255}，无软边 |
| 用色都在灰阶内 | 每个不透明像素都落在所属灰阶套内，越界数为 **0** |
| 无杂色 | 非灰阶色必须是登记过的平涂纯色 |

本工具产出 RGB（背景为平坦白），因此 alpha 项恒为通过 —— 保留它是为了与产线验收口径一致、输出可直接对照。

导出时这份验收结果会写进同名 `.json`。

## 6. 与产线的一致性

这个工具**不是重新实现**，而是 `mengshi-art-workflow/scripts/` 下 `posterize.py` 与 `pixelize_oe.py` 的逐行移植；每一处 dtype、运算顺序、常量都保持一致，并由测试守住：

```bash
python tests/test_consistency.py   # 与真实 CLI 逐像素比对
python tests/test_api.py           # 起真实服务走完整 HTTP 流程
python tests/test_web_assets.py    # 前端静态资源自洽性
python tests/test_browser.py       # 无头浏览器冒烟（真跑一遍界面）
```

`test_browser.py` 用本机 Edge / Chrome 的 headless 模式加载真实页面：
`--dump-dom` 取回 **JS 执行之后** 的 DOM（`#controls` 在 HTML 里是空的，
里面 17 个控件全靠 JS 生成，dump 出来是空的就是脚本挂了），再扫一遍
控制台有没有 `Uncaught` / `is not defined`，最后截图确认页面真的渲染出像素。
本机没有 Edge / Chrome 时记 SKIP，不算失败。

`test_consistency.py` 的做法是：**在真实图片上真的去调产线脚本**，再把它的输出与工具的输出做逐像素比对，要求 0 个像素不同。覆盖 5 种降采样策略、`keep-thin`、收档、gamma / 对比度 / rec709 等分支，以及"posterize.py + pixelize_oe.py 两个脚本串起来"的端到端对照。

## 7. 目录结构

```
pixcelOE-TOOL/
  app.py                启动入口（选端口、开浏览器）
  server/api.py         HTTP 接口 + 静态资源服务（标准库 http.server）
  core/
    palette.py          调色板加载、档位推导
    algorithm.py        算法核心（产线脚本的逐行移植）
    pipeline.py         串联各步 + 轮廓扩展缓存
    validate.py         4 项交付验收
  web/                  index.html / style.css / app.js
  data/palette.json     内置调色板（随工具分发，离线可用）
  outputs/              导出的 PNG 与 .json 元数据
  tests/                四组测试
  启动.bat              Windows 双击启动
```

**缓存**：整条链路里只有「轮廓扩展」是昂贵的（640×960 约数百毫秒），且它只依赖 `patch / thickness / keep-thin` 与输入图。所以改 factor、降采样策略、调色板、收档数时都会复用上一次的扩展结果，拖动滑块基本是秒回。

## 8. 常见问题

**Q：拖进去没反应？**
图片必须能被 Pillow 解码（PNG / JPG / WEBP / BMP）。单张上限 64 MB、4000 万像素。

**Q：像素块大小（factor）会受图片尺寸限制吗？**
不会。以前要求宽高能被 factor 整除，现在**任意值都能用**：尺寸对不齐时自动用「边缘复制」补齐最后一行/列的像素块，不裁内容、不报错，输出尺寸自动向上取整（例如 640×960 用 factor=3 → 214×320）。

**Q：颜色被抹成灰了？**
检查「量化档数」。若上游已经做过色调分离且保留了颜色，把「量化档数」设为 0，或勾选「跳过调色板量化」。

**Q：和我在命令行跑的结果不一样？**
先确认参数完全一致（尤其是 `thickness`、`--levels`、`--downsample` 这几个有默认值的）。`tests/test_consistency.py` 已经证明：参数一致时输出逐像素相同。

**Q：端口被占用？**
`python app.py --port 9000`，或直接双击 `启动.bat`（会自动往后找可用端口）。
